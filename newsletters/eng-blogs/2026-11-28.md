## Outages and postmortems

**Allstate Digital Outage**
Allstate's website and mobile application experienced a significant technology outage that began on Monday morning, November 23, 2026, and was still ongoing on Friday, November 27, 2026, extending into its fifth day. This disruption left customers across the United States unable to access their accounts, review policy details, pay bills, or file claims. Local insurance agents were also impacted, managing inquiries but limited by the system downtime. Allstate has assured customers that they will not lose coverage or be charged late fees if they were unable to make payments due to the outage.

Allstate has not issued a formal statement regarding the root cause of the outage. News reports indicate there is no public evidence suggesting a cyberattack or compromised customer data. However, some reports speculate the incident might be linked to system upgrades on aging infrastructure, a trend observed in other recent service disruptions, particularly as artificial intelligence accelerates the discovery of software vulnerabilities in legacy systems. The company has utilized automated responses on social media to address customer concerns. No details have been published regarding how the issue was fixed or what changes will be implemented. The prolonged nature of this outage, coupled with a lack of detailed communication, underscores the critical need for robust incident response protocols and transparent communication during widespread service disruptions.

The underlying infrastructure for the e-prescription system is managed by Gematik, Germany's digital agency for the health service. While this specific incident was short-lived, previous reports from August 2025 highlighted repeated outages and significant disruptions to the e-prescription system over several days, affecting tens of thousands of patients. Pharmacists have previously voiced concerns about the system's unreliability and called for greater flexibility to dispense medications during periods of downtime. No official postmortem or details on the specific fix for this Medisign card fault have been published. This incident highlights that even short outages in critical healthcare IT systems can impede essential services, emphasizing the necessity for high availability and resilient design, especially for components like smart card authentication.

## Grab Engineering: Testing AI Coding Agents with Git History

Grab Engineering has developed a novel method to objectively measure whether a knowledge base improves the performance of their internal AI coding agents. The challenge was that subjective opinions on context usefulness are unreliable, public benchmarks don't reflect Grab's specific codebase, and the knowledge base constantly updates. Adding more context could even degrade agent performance and increase costs.

Their solution involves treating every merged Git change as a solved problem, an "exam with an answer key." They created a replay loop that works as follows: first, recent merged requests are selected. Then, the original request is scrubbed of any solution details. The repository is rewound to the exact commit state before the merge. Two identical coding agents are then run with the same request and time budget: one agent plans solely from the code, and the other's prompt includes the knowledge base skill. Finally, an LLM grader scores each agent's plan against the actual merged diff using a fixed rubric, and the scores are compared.

The knowledge base itself is built in two passes. The first pass uses plain code analysis to extract syntax trees, entry points, imports, configuration keys, and call graphs. The second pass employs LLM sub-agents to write summaries and flow documents on top of this structure, with a verifier checking each batch. This knowledge base lives in Git, and updates trigger a "knowledge merge request" for service owners to approve. This systematic, data-driven approach provides a quantitative measure of the knowledge base's effectiveness. For a senior performance engineer, this demonstrates a sophisticated strategy for validating the impact of complex, evolving systems like AI agents. The concept of using historical changes as ground truth for performance evaluation is a powerful pattern for any system where objective measurement of improvement is challenging.

## Cloudflare Blog: Probing DNS at Cloudflare

Cloudflare's DNS team faced a significant challenge in detecting DNS failures, which are often slow, distributed, and partial in their impact. They experienced this firsthand when a scheduling bug in a service publishing DNS records left some changes unpublished for hours. This resulted in new hostnames being slow to resolve and certificate issuance delays, even though the service itself appeared healthy. They needed a way to test DNS as customers experience it: continuously, from every data center, and against production environments.

Their solution was to extend Flamingo, Cloudflare's existing end-to-end testing framework, to support DNS probing. Flamingo, originally designed for complex multi-step HTTP testing, is a Rust-based tool that runs hundreds of millions of tests daily against Cloudflare's edge. Its modular architecture allows teams to extend its capabilities to new networking protocols. They achieved this by reframing the "request" step in Flamingo's custom domain-specific language (DSL) as a generic "action." They then added a `DnsQuery` action to their system's action enumeration and a `Dns` output to the action output. This design decouples the specific action logic from the higher-level test scheduling and resource management.

By integrating DNS testing into Flamingo, Cloudflare can now measure DNS propagation and use these measurements to decide whether a release proceeds or is rolled back. The use of a simple DSL for test creation also simplifies debugging, as users debug the system under test rather than complex test code. For a senior performance engineer, this highlights the critical importance of comprehensive, real-world end-to-end testing for fundamental network services. The modular, action-based design of Flamingo and its custom DSL offer valuable insights into building scalable, maintainable, and debuggable testing infrastructure that can adapt to new protocols and complex distributed systems.

## Microsoft .NET Blog: Running Local AI Models in .NET Apps with Llama on Windows

Microsoft has introduced Llama on Windows, a tray application designed to simplify running AI models locally within .NET applications. The motivation behind this is to enable developers to keep prompts and responses on their personal computers, work offline after downloading models, and experiment without incurring per-request costs, bypassing the typical complexities of finding, downloading, and setting up local AI model servers.

Llama on Windows, built with .NET 10 and WinUI 3 and powered by llama.cpp, resides in the system tray. It allows users to browse and download models recommended for their hardware from the Hugging Face Hub, and interact with them via a browser chat or an Alt+Space overlay. Under the hood, Llama manages a llama.cpp server, which runs on `http://localhost:9931` and provides endpoints compatible with the OpenAI API format, such as `/v1/chat/completions` and `/v1/models`. Models are loaded when used and automatically unloaded after five minutes of inactivity to manage memory efficiently.

For .NET developers, this means they can leverage existing OpenAI client libraries, such as `Microsoft.Extensions.AI.OpenAI` with `IChatClient`, by simply configuring the endpoint to point to the local Llama server. No API key is required for local interactions. The blog post provides a C# file-based application example demonstrating how to list available models and initiate a chat session. For a senior software engineer, particularly one focused on .NET, this offers a direct and streamlined path to integrating local AI capabilities into applications, enhancing privacy, enabling offline functionality, and providing a cost-effective environment for AI experimentation and development.
