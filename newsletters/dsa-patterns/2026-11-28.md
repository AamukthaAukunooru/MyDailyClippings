Today, we're tackling a classic problem that often appears in coding interviews: the **Majority Element**. It's LeetCode problem 169, rated as easy, but it teaches a surprisingly clever and efficient pattern.

### The Problem: Finding the Overwhelming Winner

Imagine a political election where votes are cast for different candidates. We have a list of all the votes, represented as an array of numbers. Our goal is to find the candidate who won by an overwhelming margin: specifically, the one who received more than half of all the votes. This is the **majority element**. The problem guarantees that such an element always exists in our array.

Let's take a small example: suppose our array of votes, `nums`, is `[2, 2, 1, 1, 1, 2, 2]`.
Here, the total number of votes, N, is seven. Half of N is three and a half. So, we're looking for an element that appears strictly more than three and a half times, meaning at least four times.
If we count them:
The number `2` appears four times.
The number `1` appears three times.
So, `2` is our majority element because it appears four times, which is more than three and a half.

How would you approach this? A straightforward way, often called the **brute force** approach, would be to pick each unique number in the array, then iterate through the entire array again to count how many times that number appears. If its count exceeds N over two, we've found our majority element.
For our example:
1. Pick `2`. Iterate through `[2, 2, 1, 1, 1, 2, 2]`. Count `2`s: four. Four is greater than three and a half. So, `2` is the majority element. We return `2`.
This works, but consider an array with a million elements. For each element, we might scan the array again. This leads to a **time complexity** of roughly N squared, which is very slow for large arrays. Can we do better? Absolutely.

### The Key Insight: Boyer-Moore Voting Algorithm

The key to solving this problem efficiently lies in a clever technique called the **Boyer-Moore Voting Algorithm**. It's a beautiful example of how a strong problem constraint, like "a majority element *always* exists," can lead to an incredibly simple and efficient solution.

Let's go back to our election analogy. Imagine you're counting votes, but you only care about the leading candidate. You pick a candidate, and every time you see their vote, you increment their score. Every time you see a vote for someone else, you decrement their score. If their score drops to zero, it means they've been "cancelled out" by other candidates. At that point, you simply pick the *next* vote you see as your new leading candidate.

Why does this work? Because the majority element has more than half the votes. This means it has more votes than *all other candidates combined*. Even if it faces off against every single other vote, it will still have votes left over. All the non-majority votes will eventually cancel each other out, or be cancelled out by the majority element. The majority element, however, can never be fully cancelled out by the minority votes. It will always be the last one standing, or at least one of its instances will be.

### Step-by-Step: How Boyer-Moore Works

Let's walk through the Boyer-Moore Voting Algorithm with our example: `nums = [2, 2, 1, 1, 1, 2, 2]`.
We'll use two variables:
1.  `candidate`: This will store our current guess for the majority element.
2.  `count`: This will track the "score" for our `candidate`.

We initialize `candidate` to nothing and `count` to zero. Then, we iterate through the `nums` array, one element at a time:

*   **Step 1: Process `2`**
    *   Our `count` is currently zero. This means we don't have a candidate yet, or our previous candidate was cancelled out.
    *   So, we set our `candidate` to the current number, `2`.
    *   We increment `count` to one.
    *   Current state: `candidate = 2`, `count = 1`.

*   **Step 2: Process `2`**
    *   The current number, `2`, is the same as our `candidate`, `2`.
    *   We increment `count`.
    *   Current state: `candidate = 2`, `count = 2`.

*   **Step 3: Process `1`**
    *   The current number, `1`, is different from our `candidate`, `2`.
    *   We decrement `count`.
    *   Current state: `candidate = 2`, `count = 1`.

*   **Step 4: Process `1`**
    *   The current number, `1`, is different from our `candidate`, `2`.
    *   We decrement `count`.
    *   Current state: `candidate = 2`, `count = 0`. Notice how `2` and `1` "cancelled each other out" twice.

*   **Step 5: Process `1`**
    *   Our `count` is currently zero.
    *   We set our `candidate` to the current number, `1`.
    *   We increment `count` to one.
    *   Current state: `candidate = 1`, `count = 1`.

*   **Step 6: Process `2`**
    *   The current number, `2`, is different from our `candidate`, `1`.
    *   We decrement `count`.
    *   Current state: `candidate = 1`, `count = 0`. Again, `1` and `2` cancelled each other out.

*   **Step 7: Process `2`**
    *   Our `count` is currently zero.
    *   We set our `candidate` to the current number, `2`.
    *   We increment `count` to one.
    *   Current state: `candidate = 2`, `count = 1`.

We've reached the end of the array. The algorithm states that the value stored in `candidate` at the end of this single pass is the majority element. In our case, it's `2`, which is correct!

### Efficiency and Alternatives

The Boyer-Moore Voting Algorithm is incredibly efficient.
*   **Time Complexity**: We only iterate through the array once. This makes its time complexity **O(N)**, where N is the number of elements in the array. This is the fastest possible time complexity, as we must at least look at each element once.
*   **Space Complexity**: We only use two variables, `candidate` and `count`, regardless of the size of the array. This means its space complexity is **O(1)**, or constant space. This is also optimal, as we don't use any extra data structures that grow with the input size.

Let's quickly compare this to other common approaches:

1.  **Using a Hash Map or Dictionary**: We could iterate through the array, storing each number and its frequency in a hash map. Then, we iterate through the hash map to find the number whose count is greater than N over two.
    *   Time Complexity: O(N) for building the map, O(K) for checking (where K is the number of unique elements, worst case O(N)). Overall, O(N).
    *   Space Complexity: O(N) in the worst case, if all elements are unique.
    While O(N) time is good, O(N) space is not as optimal as Boyer-Moore's O(1) space.

2.  **Sorting the Array**: If we sort the array, all identical elements will be grouped together. Since the majority element appears more than N over two times, it will always occupy the middle position of the sorted array. For example, if N is seven, the element at index three (using zero-based indexing) will always be the majority element.
    *   Time Complexity: O(N log N) because sorting typically takes this long.
    *   Space Complexity: O(log N) or O(N) depending on the sorting algorithm used.
    This approach is simpler to reason about but less efficient than Boyer-Moore in terms of time complexity.

The Boyer-Moore Voting Algorithm stands out because it achieves optimal time and space complexity by cleverly exploiting the problem's guarantee.

### Edge Cases and What's Next

What about **edge cases**?
*   If the array contains only one element, say `[7]`, our algorithm works perfectly: `candidate` becomes `7`, `count` becomes `1`, and `7` is returned.
*   The problem statement explicitly guarantees that a majority element *always exists*. This is crucial. If this guarantee were removed, the Boyer-Moore algorithm would still return a `candidate`, but we wouldn't know for sure if it's actually a majority element. In that scenario, you'd need a **second pass** through the array to count the occurrences of the `candidate` returned by the algorithm and verify if its count indeed exceeds N over two. If it doesn't, then no majority element exists. This verification step would still keep the overall time complexity at O(N) and space complexity at O(1).

This problem is a fantastic introduction to a pattern that can be generalized. A common **follow-up question** in interviews is:
"Find all elements that appear more than N over three times." This is LeetCode problem 229, **Majority Element II**.
The insight here is that if an element appears more than N over three times, there can be at most two such elements. The Boyer-Moore algorithm can be extended to handle this by tracking two `candidates` and two `counts`. If a number matches neither candidate, and one of the counts is zero, we assign it as a new candidate. Otherwise, we decrement both counts. Again, a second pass is needed to verify the two potential candidates.

The core idea of "cancelling out" elements is powerful. It allows us to process large amounts of data in a single pass with minimal extra memory, making it an excellent technique to have in your toolkit.

### Recap

Today, we explored the Majority Element problem, where we find the number appearing more than N over two times in an array. We learned about the **Boyer-Moore Voting Algorithm**, a brilliant technique that uses a simple "candidate" and "count" system to effectively cancel out non-majority elements. This algorithm achieves optimal **O(N) time complexity** and **O(1) space complexity**, making it superior to brute force, hash map, or sorting approaches. Its elegance and efficiency make it a valuable pattern for your coding interview preparation.
