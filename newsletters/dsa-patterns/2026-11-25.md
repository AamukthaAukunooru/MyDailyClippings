Have you ever tried to compare two complex objects to see if they are truly identical? Maybe two versions of a document, or two blueprints for a building? It’s not enough for them to just *look* similar; every detail, every component, has to match up perfectly. In the world of data structures, we often face a similar challenge: comparing two **binary trees**. How do we determine if two binary trees are exactly the same, down to their structure and the values held by their nodes?

This is the core idea behind today's problem, "Same Tree," LeetCode problem number 100. It's a fundamental problem that introduces us to the power of **recursion** and **Depth-First Search** in tree traversals.

## What Does "Same Tree" Mean?

Let's start by defining what we mean by "same." Given two binary trees, let's call them `p` and `q`, we want to check if they are structurally identical *and* if their nodes have the same values.

Imagine `p` is represented as `[1, 2, 3]`. This usually means the root is 1, its left child is 2, and its right child is 3. If `q` is also `[1, 2, 3]`, then they should be considered the same.

Now, consider `p` as `[1, 2]` and `q` as `[1, null, 2]`. Here, `p` has a root of 1 and a left child of 2. `q` also has a root of 1, but its left child is empty, and its right child is 2. Even though both trees contain the numbers 1 and 2, their structure is different. So, these two trees are *not* the same.

The problem asks us to write a function that takes the roots of two binary trees, `p` and `q`, and returns `true` if they are the same, and `false` otherwise.

## Building Intuition: A Recursive Comparison

How would you compare two trees by hand? You'd probably start at the very top, at their **roots**.
First, you'd check if both roots exist. If one exists and the other doesn't, they can't be the same. If neither exists, well, two empty trees are certainly the same.
If both roots exist, you'd then compare their **values**. If their values are different, the trees are not the same.
If their values *are* the same, then you've passed the first hurdle. But that's not enough! You still need to check their children. You'd move on to compare their **left children** and then their **right children**.

This process sounds very repetitive, doesn't it? "Compare the roots, then compare their left children, then compare their right children..." This is a classic indicator that **recursion** is a powerful tool for solving this problem. We can define a function that checks if two nodes (and their entire subtrees) are the same. This function will then call itself for the left and right children. This pattern is a form of **Depth-First Search (DFS)**, where we explore one path of the tree as far as possible before backtracking.

## The Optimal Approach: Recursive Depth-First Search

Let's formalize this intuitive recursive approach. We'll define a function, let's call it `isSameTree`, that takes two nodes, `node1` and `node2`, as arguments. This function will return `true` if the subtrees rooted at `node1` and `node2` are identical, and `false` otherwise.

Here are the steps for our `isSameTree` function:

1.  **Base Case 1: Both nodes are empty.**
    If `node1` is `null` (meaning it's an empty node) AND `node2` is also `null`, then we've reached the end of a path in both trees simultaneously. These parts are identical. So, we return `true`.

2.  **Base Case 2: One node is empty, the other is not.**
    If `node1` is `null` BUT `node2` is NOT `null`, or vice versa (if `node2` is `null` BUT `node1` is NOT `null`), then the structures don't match. One tree has a node where the other doesn't. So, we return `false`.

3.  **Base Case 3: Both nodes exist, but their values differ.**
    If both `node1` and `node2` exist (meaning they are not `null`), but their stored **values** are different, then the trees are not the same. So, we return `false`.

4.  **Recursive Step: Both nodes exist and have the same value.**
    If we've passed all the above checks, it means `node1` and `node2` both exist and have identical values. Now, we need to ensure that their entire subtrees are also identical. This is where the recursion comes in.
    We need to check two things:
    *   Are their left subtrees the same? We do this by recursively calling `isSameTree` on `node1.left` and `node2.left`.
    *   Are their right subtrees the same? We do this by recursively calling `isSameTree` on `node1.right` and `node2.right`.
    For the current nodes to be considered "the same," *both* of these recursive calls must return `true`. So, we return the result of `(isSameTree(node1.left, node2.left) AND isSameTree(node1.right, node2.right))`.

Let's trace this with our first example: `p = [1, 2, 3]` and `q = [1, 2, 3]`.

*   We start with `isSameTree(root_p, root_q)`.
    *   `root_p` has value 1, `root_q` has value 1. They are not null and their values match.
    *   We proceed to the recursive step.
    *   First, we check the left children: `isSameTree(p.left, q.left)`.
        *   `p.left` has value 2, `q.left` has value 2. They are not null and their values match.
        *   We proceed to the recursive step for these nodes.
        *   Check `isSameTree(p.left.left, q.left.left)`. Both are `null`. Base Case 1 applies, returns `true`.
        *   Check `isSameTree(p.left.right, q.left.right)`. Both are `null`. Base Case 1 applies, returns `true`.
        *   Since both left and right sub-calls returned `true`, `isSameTree(p.left, q.left)` returns `true`.
    *   Now, we check the right children: `isSameTree(p.right, q.right)`.
        *   `p.right` has value 3, `q.right` has value 3. They are not null and their values match.
        *   We proceed to the recursive step for these nodes.
        *   Check `isSameTree(p.right.left, q.right.left)`. Both are `null`. Base Case 1 applies, returns `true`.
        *   Check `isSameTree(p.right.right, q.right.right)`. Both are `null`. Base Case 1 applies, returns `true`.
        *   Since both left and right sub-calls returned `true`, `isSameTree(p.right, q.right)` returns `true`.
    *   Since both `isSameTree(p.left, q.left)` and `isSameTree(p.right, q.right)` returned `true`, the initial call `isSameTree(root_p, root_q)` returns `true`.

This approach systematically compares every corresponding node in both trees. If at any point we find a mismatch in structure or value, we immediately know the trees are not the same and can stop.

## Time and Space Complexity

Let's analyze how efficient this recursive solution is.

*   **Time Complexity:** The algorithm visits each node in both trees exactly once. In the worst case, we might have to visit all nodes in both trees to confirm they are identical, or to find the very last differing node. If `N` is the number of nodes in the larger of the two trees, the time complexity is **O(N)**. We do a constant amount of work at each node (checking for null, comparing values, making two recursive calls).

*   **Space Complexity:** The space complexity is determined by the maximum depth of the **recursion stack**. In the worst case, if the trees are skewed (like a linked list, where each node only has one child), the recursion depth can be equal to the number of nodes, `N`. So, the space complexity would be **O(N)**. However, if the trees are balanced, the height of the tree is logarithmic with respect to the number of nodes, `log N`. In this best-case scenario, the space complexity would be **O(log N)**. Generally, we state the worst-case, so **O(N)** space.

## Edge Cases and Follow-ups

This recursive definition handles several edge cases naturally:

*   **Both trees are empty:** If `p` and `q` are both `null` from the start, our first base case `(node1 == null && node2 == null)` will immediately return `true`. This is correct; two empty trees are the same.
*   **One tree is empty, the other is not:** If `p` is `null` but `q` has a root node, the second base case `(node1 == null || node2 == null)` will trigger, returning `false`. This is also correct.
*   **Single-node trees:** If `p = [5]` and `q = [5]`, they will be deemed the same. If `p = [5]` and `q = [7]`, they will be deemed different due to value mismatch.

**Follow-up questions** an interviewer might ask:

1.  **Can this be solved iteratively?** Yes, you can solve this using an iterative approach with a stack (for iterative DFS) or a queue (for **Breadth-First Search, BFS**).
    *   **Iterative DFS:** You would push pairs of nodes onto a stack. In each step, pop a pair, perform the same null and value checks, and if they match, push their left children (as a pair) and then their right children (as a pair) onto the stack.
    *   **BFS:** You would use a queue and enqueue pairs of nodes. In each step, dequeue a pair, perform the checks, and if they match, enqueue their left children (as a pair) and then their right children (as a pair).
    The logic remains very similar, just the mechanism of traversal changes from recursion to explicit stack/queue management.

2.  **What if we needed to find *where* the trees differ?** Instead of just returning `true` or `false`, you could modify the function to return a list of paths or node values where the discrepancy was found. This would involve collecting information during the traversal rather than just a boolean result.

## Why This Pattern Matters: Related Problems

The "Same Tree" problem is a fantastic introduction to comparing tree structures and using recursion. The core pattern of recursively comparing corresponding parts of two structures is widely applicable. Here are a few related problems that use very similar ideas:

1.  **Symmetric Tree (LeetCode 101):** This problem asks you to check if a binary tree is a mirror image of itself. It's almost identical to "Same Tree," but instead of comparing `p.left` with `q.left`, you compare `p.left` with `p.right` in a mirrored fashion. You'd define a helper function that takes two nodes and checks if one is the mirror of the other.

2.  **Subtree of Another Tree (LeetCode 572):** Here, you are given two non-empty binary trees, `root` and `subRoot`, and you need to check if `subRoot` is a subtree of `root`. A subtree of `root` is a tree that consists of a node in `root` and all of its descendants. The tree `root` itself can be considered a subtree. This problem involves traversing the `root` tree and, at each node, calling a function very similar to our `isSameTree` to check if the current node in `root` and its subtree are identical to `subRoot`.

3.  **Invert Binary Tree (LeetCode 226):** While not a comparison problem, "Invert Binary Tree" is another classic easy problem that relies on recursive Depth-First Search. It asks you to flip a tree upside down, swapping left and right children at each node. It reinforces the concept of performing an action at a node and then recursively doing the same for its children.

These problems demonstrate how a fundamental understanding of tree traversal and recursion, gained from a simple problem like "Same Tree," can be adapted to solve a variety of structural challenges in tree data structures.

## Recap

Today, we explored the "Same Tree" problem, a classic introduction to comparing binary trees. We learned that determining if two trees are identical in both structure and value is best solved using **recursion** and a **Depth-First Search** pattern. The algorithm systematically compares nodes, checking for nulls and value mismatches, and recursively verifying left and right subtrees. This elegant solution offers **O(N) time complexity** and **O(N) space complexity** in the worst case, making it an efficient way to tackle tree comparison.
