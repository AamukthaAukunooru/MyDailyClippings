Hello and welcome to DSA Explained, the daily learning series for My Daily Clippings. Today, we're unraveling a classic interview problem that often appears deceptively simple: building the **Longest Palindrome** from a given set of characters. This is LeetCode problem 409, an easy one, but it teaches a powerful lesson about character frequency and greedy approaches.

## What's in a Palindrome?

What do words like "madam," "racecar," or even the famous phrase "A man, a plan, a canal: Panama" have in common? They're all **palindromes**. A palindrome is a sequence of characters that reads the same forwards and backwards. Simple enough, right?

Today's problem isn't asking you to find the longest palindromic *substring* within a larger string – that's a different, harder problem. Instead, you're given a string, and your task is to figure out the *length* of the longest possible palindrome you can construct using the characters available in that string. You can use each character as many times as it appears in the original string.

Let's take a small example. Suppose your input string is "abccbdd". What's the longest palindrome we can build using these letters? We have one 'a', two 'b's, two 'c's, and two 'd's. We could make "dcbabcd", which has a length of seven. Notice how it uses all the 'b's, 'c's, and 'd's, and the single 'a' sits right in the middle.

The core idea here is to understand the structure of a palindrome. If a string reads the same forwards and backwards, it means that for every character on one side, there must be a matching character on the other side. Think of "racecar": 'r' matches 'r', 'a' matches 'a', 'c' matches 'c', and the 'e' is in the middle, having no pair. This tells us something crucial: most characters in a palindrome must appear an **even number of times**. At most, only *one* character can appear an **odd number of times**, and that character will occupy the very center of our palindrome.

## The Brute Force Trap and the Key Insight

When faced with a problem like this, a common initial thought might be to try and generate all possible permutations of the given characters and then check each one to see if it's a palindrome. However, if our input string has, say, fifty characters, the number of permutations would be fifty factorial – an astronomically large number that would take far longer than the age of the universe to compute. This is clearly not a viable approach.

The problem isn't about finding a specific arrangement by trial and error. It's about maximizing the length given the constraint of forming a palindrome. This is where our understanding of palindrome structure becomes the **key insight**.

Since a palindrome needs pairs of characters (one for the left side, one for the right), we should prioritize using as many pairs as possible. If we have three 'A's, we can use two of them to form a pair ('A' on the left, 'A' on the right), and one 'A' will be left over. If we have four 'B's, we can use all four, forming two pairs ('B' 'B' on the left, 'B' 'B' on the right).

The strategy becomes clear:
1.  Count how many times each character appears in the input string.
2.  For each character, take all its **even counts** to contribute to the palindrome's length. For example, if 'A' appears five times, we can use four of them (two pairs). If 'B' appears two times, we use both.
3.  If, after taking all the even counts, there's *any* character that had an **odd count** (meaning one character was left over, like the fifth 'A' in our example), we can use *one* of these leftover characters to form the very center of our palindrome. We can only have one central character, so even if multiple characters have odd counts, we can only pick one to be the center.

This approach is **greedy** because at each step, we're making the locally optimal choice (using as many pairs as possible) to achieve the globally optimal solution (the longest possible palindrome). The pattern it uses is **frequency counting** combined with a greedy strategy.

## The Optimal Approach: Step by Step

Let's walk through the optimal algorithm using our example string: `s = "abccbdd"`.

**Step 1: Count Character Frequencies**
First, we need to know how many of each character we have. We can use a **hash map** or an array (since we're dealing with English letters, an array of size 52 for both lowercase and uppercase would work well) to store these counts.

For `s = "abccbdd"`:
*   'a': 1
*   'b': 2
*   'c': 2
*   'd': 2

**Step 2: Initialize Length and Odd Flag**
We'll maintain a variable, let's call it `total_length`, initialized to zero. This will store the length of the palindrome we're building. We'll also need a boolean flag, `has_odd_count`, initialized to false. This flag will tell us if we've encountered at least one character with an odd count.

`total_length = 0`
`has_odd_count = false`

**Step 3: Process Character Counts**
Now, we iterate through our character counts:

*   **For 'a':** The count is 1.
    *   We can take `(1 / 2) * 2 = 0` characters to form pairs. So, we add 0 to `total_length`. `total_length` remains 0.
    *   Since the count (1) is odd, we set `has_odd_count` to true.
    *   Our state: `total_length = 0`, `has_odd_count = true`.

*   **For 'b':** The count is 2.
    *   We can take `(2 / 2) * 2 = 2` characters to form pairs. So, we add 2 to `total_length`. `total_length` becomes 2.
    *   The count (2) is even, so `has_odd_count` remains true (because 'a' already made it true).
    *   Our state: `total_length = 2`, `has_odd_count = true`.

*   **For 'c':** The count is 2.
    *   We can take `(2 / 2) * 2 = 2` characters to form pairs. So, we add 2 to `total_length`. `total_length` becomes 4.
    *   The count (2) is even, so `has_odd_count` remains true.
    *   Our state: `total_length = 4`, `has_odd_count = true`.

*   **For 'd':** The count is 2.
    *   We can take `(2 / 2) * 2 = 2` characters to form pairs. So, we add 2 to `total_length`. `total_length` becomes 6.
    *   The count (2) is even, so `has_odd_count` remains true.
    *   Our state: `total_length = 6`, `has_odd_count = true`.

**Step 4: Add the Center Character (if possible)**
After iterating through all characters, we check our `has_odd_count` flag.
*   If `has_odd_count` is true (which it is in our example), it means there was at least one character with an odd count. We can use one of these single, leftover characters to form the center of our palindrome. So, we add 1 to `total_length`.
*   `total_length` becomes `6 + 1 = 7`.

**Step 5: Return Result**
The final `total_length` is 7. This is the length of the longest palindrome we can build from "abccbdd". An example palindrome would be "dcbabcd".

## Time and Space Complexity

Let's analyze the resources our algorithm uses:

*   **Time Complexity:**
    *   The first step is to iterate through the input string `s` to count character frequencies. If the string has `N` characters, this takes **O(N)** time.
    *   The second step is to iterate through the character counts. Since we're dealing with English letters (both lowercase and uppercase), there are at most 52 unique characters. This is a constant number, let's call it `K`. So, iterating through these counts takes **O(K)** time.
    *   Combining these, the total time complexity is **O(N + K)**. Since `K` is a small constant (52), we can simplify this to **O(N)**. This is very efficient, as we only need to look at each character in the input string once.

*   **Space Complexity:**
    *   We use a hash map or an array to store the character counts. The maximum number of distinct characters we'd need to store is `K` (52 for English letters).
    *   Therefore, the space complexity is **O(K)**. Since `K` is a constant, we can say the space complexity is **O(1)**, meaning it uses a constant amount of extra memory regardless of the input string's length (as long as the character set is fixed).

## Edge Cases and Common Misconceptions

Let's consider a few edge cases:

*   **Empty string:** If the input `s` is an empty string `""`, our frequency counts will all be zero. `total_length` will remain zero, and `has_odd_count` will remain false. The algorithm correctly returns 0.
*   **Single character string:** If `s = "a"`, the count for 'a' is 1. `total_length` starts at 0. We add 0 for pairs. `has_odd_count` becomes true. Finally, we add 1 for the center. The result is 1. Correct.
*   **String with all same characters:** If `s = "aaaaa"`, the count for 'a' is 5. We add `(5 / 2) * 2 = 4` to `total_length`. `has_odd_count` becomes true. Finally, we add 1 for the center. The result is 5. Correct.

A common misconception, as mentioned earlier, is confusing this problem with finding the longest palindromic *substring*. Remember, here we can rearrange the characters freely to *build* a palindrome. The characters don't have to be contiguous in the original string. This distinction is crucial and simplifies the problem significantly.

Another point to clarify: if multiple characters have an odd count (e.g., `a: 3, b: 3, c: 1`), we can only use *one* of them as the center. The other leftover odd-count characters simply cannot be used. Our `has_odd_count` flag correctly handles this by simply checking if *any* odd count exists, and then adding 1 to the total length *at most once*.

## Why This Matters

This problem, despite being "easy," is a fantastic illustration of several important concepts in computer science and algorithm design:

1.  **Frequency Counting:** It highlights the power of simply counting occurrences of elements. This technique is fundamental for many string manipulation problems, anagram checks, and even some data compression algorithms.
2.  **Greedy Approach:** The solution is greedy because it makes the best local choice (using all available pairs) to build towards the optimal global solution (the longest palindrome). Recognizing when a greedy approach is applicable is a valuable skill.
3.  **Understanding Problem Constraints:** The key to solving this problem efficiently is understanding that we're *building* a palindrome, not finding a *substring*. This changes the entire problem space and allows for a much simpler solution.
4.  **Character Set Considerations:** Thinking about the size of the character set (e.g., ASCII, Unicode) helps in choosing the right data structure for frequency counting (array vs. hash map).

## Follow-up Questions and Related Problems

An interviewer might ask a follow-up question: "Instead of just the length, can you return *one* of the longest palindromes itself?"
To do this, you would extend the algorithm:
1.  After counting frequencies, build the "left half" of the palindrome. For each character with an even count `C`, append `C/2` copies of that character to a string builder. For characters with odd counts, append `(C-1)/2` copies.
2.  Identify the single character that will be the center. If multiple characters had odd counts, pick any one of them.
3.  Construct the final palindrome by concatenating: `left_half + center_character + reverse(left_half)`.

For example, with "abccbdd":
*   `a: 1`, `b: 2`, `c: 2`, `d: 2`.
*   Left half: `b` (from `b:2`), `c` (from `c:2`), `d` (from `d:2`). So, `bcd`.
*   Center: `a` (from `a:1`).
*   Reverse of left half: `dcb`.
*   Resulting palindrome: `bcda dcb` or `dcb a bcd` (order of characters in left half doesn't matter, as long as they are paired). Let's say we build `bcd` for the left half. Then `bcd` + `a` + `dcb` gives `bcdadcb`.

Related problems that use similar ideas:

1.  **Valid Anagram (LeetCode 242):** Determine if two strings are anagrams of each other. This is purely a frequency counting problem.
2.  **Permutations of a Palindrome (LeetCode 266):** Given a string, determine if a permutation of the string can be a palindrome. This is very similar to our problem, asking if `total_length` could be `N` (the length of the string) or `N-1`. It boils down to checking if at most one character has an odd count.
3.  **Group Anagrams (LeetCode 49):** Group words that are anagrams of each other. This also often involves frequency counting, where the character counts (or a sorted version of the string) act as a key for grouping.

## Recap

To summarize, the problem of finding the length of the longest palindrome buildable from a given string's characters is efficiently solved by understanding palindrome structure. We count character frequencies, sum up all pairs of characters to form the main body of the palindrome, and then add one to the total length if any character had an odd count, allowing it to form the palindrome's center. This greedy approach, based on frequency counting, offers an optimal solution with linear time and constant space complexity.
